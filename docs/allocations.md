# 当前课程用卡范围

用户于2026-10-15调整资源分配，此规则优先于历史计划中的160卡配置。

| 任务 | alias | 卡数 | 课程可用性 |
|---|---|---:|---|
| box_flow_grpo_2_bj | box2 | 16 H20 | 可用 |
| hy35_bp_bj | hy | 64 H20 | 可用 |
| box_flow_grpo_1_bj | box1 | 16 H20 | 用户预留，禁用 |
| H3_grpo | h3 | 64 H20 | 用户预留，禁用 |

当前最大并发为80卡。`allocation_policy.json` 是可审阅的规则源；控制机默认入口、单机连接、整批调度和新worker均读取该规则。用户未明确重新开放前，不向box1/h3提交课程任务。

历史计划继续保留原始版本与host index，避免改变已运行实验的含义；当前调度保留canonical host indices：box2为2–3，hy为4–11。补跑清单使用 `completion_80gpu.json`，不原地改写仍在执行的207项计划。

撤出时先冻结课程调度进程防止补位，再请求训练进程在完成当前step后保存checkpoint并退出。停止对象仅为课程进程及其已核对的子进程，不关闭或释放太极实例。10台预留节点的最终核对均无课程进程、无CUDA计算进程，共73个中断任务保留checkpoint。

73个任务仅完成1–2步，因此迁移以新attempt从相同配置重新开始，保留原中断记录，不把它们当作数值发散。加上未启动但绑定box1的30个后续任务，迁移计划共103项：71项可独立运行，30项同GPU方差对照固定hy_0/GPU0，2项deterministic重复固定hy_1/GPU0。

迁移worker等现有课程GPU锁释放后启动，复查GPU空闲，再领取任务。因此新旧队列合计不会超出这80张卡，也不会打断box2/hy正在执行的课程实验。
